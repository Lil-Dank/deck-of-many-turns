⚔ Deck of Many Turns Bridge Protocol

The WebSocket protocol between the Deck of Many Turns desktop app and its Stream Deck plugin — documented so anything else can integrate the same way: stream overlays, macro pads, home-automation buttons, other tools.

Connection

The desktop app hosts a plain WebSocket server on ws://127.0.0.1:57321 (port configurable in the app under Settings → Stream Deck bridge). No authentication, no handshake beyond the WebSocket upgrade — the server only listens on the loopback interface. Any number of clients may connect; the Stream Deck plugin is simply one of them, and the connection count shows in the app's sidebar.

  • On connect, the app immediately pushes a full state message.
  • Every state change pushes a fresh, complete state message to all clients — there are no deltas.
  • Clients send single JSON command objects; the app never replies to commands directly (the resulting state broadcast is the acknowledgement).
  • If the app is closed, reconnect with your own retry loop — the plugin retries every 3 s forever.

State message (app → client)

Sent on connect and on every change. Outside an active combat, combatants is empty and round is 0. 

{
  "type": "state",
  "language": "en",              // "en" | "de" - the app's UI language
  "currentIndex": 2,             // index into combatants of the active turn
  "round": 3,
  "combatants": [
    {
      "id": "6f0c…",             // stable per combat; use for commands
      "sourceId": "a1b2…",       // monster template id (PCs: library PC id)
      "type": "monster",         // "pc" | "monster"
      "displayName": "Goblinkrieger 2",  // localized to `language`
      "currentHp": 4,
      "maxHp": 10,
      "ac": 15,
      "isCurrentTurn": true,
      "isDowned": false,          // PCs at 0 HP stay listed, downed
      "conditions": ["Poisoned"], // canonical English values (see below)
      "concentration": null,      // spell name being concentrated on
                                  // (localized to `language`), or null
      "saveMods": {               // v3.6+; ability modifiers, so a client can
        "str": -1, "dex": 2,      // roll this creature's saving throw itself.
        "con": 0,  "int": -2,     // Absent when the creature has no scores.
        "wis": 0,  "cha": -2
      },
      "attacks": [                // rollable actions only
        {
          "id": "srd-2024_goblin.scimitar",
          "name": "Krummsäbel",   // localized to `language`
          "toHit": 4,             // null for save-based actions
          "save": null,           // e.g. "GES 13" (localized ability + DC)
          "damage": [
            { "dice": "1d6+2", "average": 5, "type": "slashing", "condition": null }
          ]
        }
      ]
    }
  ]
}
Monsters removed at 0 HP disappear from combatants entirely. Player characters stay, with isDowned: true. Names, attack names and save abilities arrive already localized; conditions values are always the canonical English strings. Player characters can carry attacks too (same shape) when the DM or a player has defined them.

Save prompts (app → client, v3.6+)

The only messages the app pushes besides state. A saving throw can be owed at any moment — damage to a concentrating character, or a spell aimed at the party — and the app asks every surface that could answer it: the DM window, the players' phones, and any connected bridge client. 

{
  "type": "savePrompt",
  "id": "9c1f…",              // answer with saveResult, quoting this id
  "kind": "concentration",     // "concentration" | "save"
  "ability": "CON",            // thrown against the DC
  "dc": 13,
  "attackName": "Bless",       // localized to `language`
  "targetIds": ["6f0c…"]       // combatants still owing the throw
}

{ "type": "savePromptClosed", "id": "9c1f…" }
First answer wins, per target. Several surfaces hold the same prompt at once, so a client should treat savePromptClosed as "put it away, somebody got there first" rather than an error. Sending a saveResult for a target that is already answered is harmless and simply ignored.

Clients older than v3.6 ignore both messages, and the app works fine without any client answering — the DM window always has the throw.

Commands (client → app)

One JSON object per WebSocket message.

CommandPayloadEffect
nextTurn {"type":"nextTurn"} Advance the turn; wraps to the next round.
prevTurn {"type":"prevTurn"} Rewind the turn; refused at round 1, first actor.
endCombat {"type":"endCombat"} End the combat immediately (no confirmation on this side).
applyDamage {"type":"applyDamage", "actorId":"6f0c…", "amount":7, "actorName":"Goblin 2", "actorType":"monster", "math":"1d6 [4] +2 = 6", "mathTypes":["slashing"], "save":{"ability":"DEX","dc":11, "die":14,"total":16, "saved":true, "attackName":"Acid Breath", "attackerName":"Wyrmling"}} Damage floors at 0 HP; monsters die and leave the order, PCs go down. The trailing fields are optional: actorName / actorType / math (v2.2+) attribute the combat-log entry to an attacker and record the dice composition (DM-side only — player phones never receive it); mathTypes (v3.1+) names the canonical damage type of each […] bracket group in math, in order (null for unknown), so the log tints the rolled numbers. save (v3.6+) reports the saving throw this target made against a save-based action; the app writes it to the log as its own entry immediately before the damage, so the card matches one produced in the app window. Omit die when the total was not rolled by the client (a physical d20 typed in), and omit total too when only the verdict is known.
saveResult {"type":"saveResult", "id":"9c1f…", "targetId":"6f0c…", "die":14, "total":16} One target's answer to a savePrompt. die is the raw d20, or null when a physical die was rolled and only the total is known. Send one per target you answered; the app decides the race and logs the throw.
applyHeal {"type":"applyHeal", "actorId":"6f0c…", "amount":5} Healing caps at max HP; revives downed PCs.
toggleCondition {"type":"toggleCondition", "actorId":"6f0c…", "condition":"Poisoned"} Adds or removes the condition (canonical English value).
clearConcentration {"type":"clearConcentration", "actorId":"6f0c…"} Ends the actor's Concentration (clears the concentration tag). No-op when not concentrating.
attackEvent {"type":"attackEvent", "sourceId":"a1b2…", "attackId":"srd-2024_goblin.scimitar", "phase":"attackHit", "roll":{"actorName":"Goblin 2", "actorType":"monster", "targetName":"Aria", "attackName":"Scimitar", "die":14,"dice":[14,9], "total":18}} Attack-flow progress report. No HP/turn change — it triggers Kenku FM sounds the DM has configured for that attack or for the global crit/hit/miss events, and (on the verdict phases attackCrit/attackHit/attackMiss) writes one combat-log line. sourceId is recommended but optional: the app can resolve the attack from attackId alone (action ids are unique). roll is optional and ignored on non-verdict phases; when a client omits it, the app still logs the verdict by resolving the attacker from the current turn or the attack id — just without the die and total. dice (v3.1+, optional) lists every d20 thrown under advantage/disadvantage — die is the kept one, and the log shows the discarded die struck through.

attackEvent phases

  • attackRoll — the d20 left the cup (fires regardless of outcome)
  • attackCrit / attackHit / attackMiss — the verdict (send exactly one; a crit implies a hit)
  • damageRoll — damage dice rolled
  • damageApplied — the damage was committed (send alongside applyDamage)

Condition values

Blinded, Charmed, Deafened, Exhaustion, Frightened, Grappled, Incapacitated, Invisible, Paralyzed, Petrified, Poisoned, Prone, Restrained, Stunned, Unconscious

Example session

> (connect ws://127.0.0.1:57321)
< {"type":"state","language":"en","currentIndex":0,"round":1,"combatants":[…]}

> {"type":"applyDamage","actorId":"6f0c…","amount":7}
< {"type":"state", …updated combatants…}

> {"type":"nextTurn"}
< {"type":"state","currentIndex":1, …}

> {"type":"endCombat"}
< {"type":"state","combatants":[],"round":0, …}

Behaviour notes

  • Unknown command types are ignored silently — safe to feature-detect by trying.
  • Malformed JSON closes nothing; the message is dropped.
  • Pressing hardware keys pulls the app's DM window to its Combat screen; attackEvent deliberately does not.
  • The protocol is unversioned; fields are only ever added, never repurposed. Treat unknown fields as forwards-compatible.

Source of truth: app/src/main/bridge.ts (server) and plugin/src/bridge.ts (reference client) in the repository.
